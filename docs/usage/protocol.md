# Protocol headers handled by the engine

[← Usage index](README.md)

Some headers are owned by the server core, never by middleware, because they
decide how the sockets physically talk to each other.

| Header | Handling |
|---|---|
| **Host** | Parsed. Exposed via `req.host()` for (virtual-host) routing. |
| **Content-Length** | Exposed via `req.content_length`. Drives body framing. |
| **Transfer-Encoding: chunked** | Exposed via `req.chunked`. The body is decoded and compacted in place (no extra buffer). |
| **Connection** | Drives the keep-alive loop. The engine emits `Connection: keep-alive` or `Connection: close` in the response. |
| **Content-Type / Content-Encoding** | Set on the response via `res.set_content_type()` / `res.set_content_encoding()`. |

The engine also writes `Content-Length` on every buffered response.

## Keep-alive

A single `HttpConnection` serves consecutive requests on one socket. The engine
reads `llhttp_should_keep_alive()`, which accounts for the HTTP version and the
`Connection` header. HTTP/1.1 defaults to keep-alive. HTTP/1.0 and an explicit
`Connection: close` end the loop after the current response.

The parser is paused on each message boundary, so a single `read()` carrying more
than one pipelined request never mixes request state. Leftover bytes are
compacted to the front of the RX buffer for the next round.

## Protocol error responses

Generated by the engine before any middleware or handler runs:

| Status | Cause |
|---|---|
| `400 Bad Request` | Malformed HTTP syntax (llhttp parse error), or a request larger than the RX buffer |
| `404 Not Found` | Unknown path |
| `405 Method Not Allowed` | Path exists, but not for this method |
| `413 Content Too Large` | Body larger than `UCHTTP_MAX_BODY_BYTES` (see [limits](security.md#dos-and-slowloris-protection)) |
| `431 Request Header Fields Too Large` | Header block larger than `UCHTTP_MAX_HEADER_BYTES` |
| `501 Not Implemented` | A method uchttp does not support (for example `TRACE`, `CONNECT`) |

All of them except `404`, `405` and `501` close the connection.
